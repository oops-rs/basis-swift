# 0001 — basis binds to other languages through UniFFI

> Status: Accepted · 2026-10-27
> Swift is the first target.

## Context

basis's in-process surface is a Rust crate, so only Rust can embed it. Its
other two surfaces, ACP and `basis spawn --json`, need a `basis` binary to run
as a subprocess. That is a cost on macOS and impossible on iOS, where an app
spawns no processes. A Swift app also wants its approver and its event view to
be its own code, running while the turn waits.

Two ways to reach Swift in process:

- **A hand-written C API.** Any language can call it, but C has no async,
  errors, lifetimes or typed callbacks, so every language must rebuild them
  in a hand-written wrapper.
- **UniFFI.** It generates that wrapper from Rust definitions. `async fn`
  becomes Swift `async`, `Result` becomes `throws`, `Arc` objects become
  classes, and a trait the host implements becomes a Swift protocol. The same
  definitions generate Kotlin, Python and Ruby, and third-party generators
  cover others.

## Decision

1. **The binding is its own repository and crate, `basis-ffi`, over the
   published `basis`.** basis gains no UniFFI derive and no FFI type, and it
   does not know this crate exists. The binding mirrors what it exposes in
   records of its own.

2. **The binding is UniFFI, and there is no public C API.** UniFFI's C layer
   is an implementation detail that changes with UniFFI. A language without a
   UniFFI generator would need a hand-written C API, as a separate crate,
   when such a consumer exists.

3. **Small, stable seams cross as types, and the event stream crosses as its
   wire line.** Options, the approval request and answer, and the run report
   are records and enums that a host switches on. An event crosses as one
   JSON `EventLine`, exactly what `basis spawn --json` writes. `Event` is
   large and grows, and it already has a versioned schema
   (`EVENT_SCHEMA_VERSION`). Mirroring it would create a second definition of
   that schema.

4. **The binding owns its tokio runtime.** A foreign caller brings no
   executor, so one multi-thread runtime lives for the process. Every
   exported `async fn` runs its work there, and a foreign `await` only waits.

5. **A foreign seam fails closed.** An approver that throws denies, and an
   observer that throws ends the run, the same rules basis applies to a
   broken hook and a refused sink write.

6. **The first cut is the run lifecycle:** open a workspace with options,
   prepare or resume a run, send a turn with an observer, an approver and a
   stop control, and read the report. Interceptors, native tools, typed
   output and a shared runtime for many workspaces come when a host needs
   them. Each is one more foreign trait or record over a seam basis already
   has.

7. **Packaging is generated by a script, not by hand.**
   `scripts/build-xcframework.sh` builds the static libraries for each Apple
   target, generates the Swift sources with the crate's own `uniffi-bindgen`,
   and assembles `BasisFFI.xcframework` under a Swift package. Swift code in
   the package is generated, apart from tests.

## Consequences

- A Swift app embeds basis in process on macOS and iOS. Tools that spawn
  (`shell`, declared tools, stdio MCP, subprocess hooks) still fail where the
  OS refuses to spawn. That is the platform's limit, not the binding's.
- A change that bumps `EVENT_SCHEMA_VERSION` breaks Swift readers the same
  way it breaks JSONL readers, and the version tells them so.
- `uniffi` is pinned to an exact version: the generated Swift and the
  compiled scaffolding must come from the same UniFFI.
- `uniffi` is MPL-2.0. Its file-level copyleft does not reach this crate's
  MIT sources.
